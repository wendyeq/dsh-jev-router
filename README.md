# dsh-jev-router

Optional Cordis plugin for choosing a concrete session model and independent per-request reasoning effort through the official `typesafe-ai/jev` evaluate API. Mount its bundle beside the Harness profile's model adapter, Session Controller, AgentLoop, and credentials plugins. The patch ships disabled; enable it with a profile override and configure `credentialRefs` with a Harness credential reference for a Vercel AI Gateway Bearer token. The plugin never reads an environment variable directly and never registers a generation adapter.

## Host

Upstream DeepSeek Harness does not provide the selector events or the `configuration-update` block this plugin uses. Run it against [wendyeq/deepseek-harness](https://github.com/wendyeq/deepseek-harness) branch `local/jev-host` at `737a4c131e` or a descendant of that commit. Tests import the sibling checkout `../deepseek-harness`.

## Selection

The model directory adds `auto/jev` and the effort directory adds `自动` (`auto/jev` internally). On the first main request, automatic model selection asks Jev to choose among the configured and currently registered model routes, then asks it for the lowest sufficient effort supported by that exact model. The model remains fixed for the Session after both evaluations succeed. Later main requests choose effort independently. Selecting `auto/jev` again invalidates the previous choice; changing candidate descriptions alone does not. A specified model remains unchanged, whether effort is automatic or specified. A child uses its parent's concrete model and effort selection method; an automatic parent without a selected model cannot supply one. The model and selection method survive Session restoration in an atomic per-Session sidecar. The evaluated effort is not a user selection. The first effort for a model route is the request-level effort (`reasoning.effort` on Responses, `reasoning_effort` on Chat Completions) and is kept in the sidecar. A later change on that same route appends one `configuration_update` before the next user message and does not rewrite the request-level effort, so the prefix cache can still hit. The new effort stays in effect until the next update. Two updates are never placed next to each other; after compaction removes the previous one, the next request records a fresh update. Chat Completions has no `configuration_update` item, so a later effort is sent as a new `reasoning_effort`. Switching the concrete model starts a new cache context and a new request-level effort. The first main request records an automatic-effort `model/selection` intent so the UI does not mistake the concrete request effort for a fixed user choice; older sessions record it on their next main request.

Only main requests ask Jev. Title and compaction requests use the concrete Session model and its adapter default effort; with no Session model they fail. Request headers and provider calls contain real registered routes, never selector ids. Evaluate sees at most eight recent user/assistant text bodies when selecting a model; effort selection can also include tool-result text, truncated to 1600 characters per result. System/developer prompts, tool arguments, reasoning blocks, and images are excluded. An empty user body, missing candidates or efforts, invalid answer, missing credential, timeout, cancellation, or oversized body fails the request. Only Jev HTTP 503 is retried, up to twice after one second each (three attempts total). Each attempt has up to five seconds, for a total ceiling of 17 seconds including delays. If all effort checks return 503, use the last valid effort actually sent for the same model, or its supported adapter default on a first request; otherwise fail. A model-selection failure still fails without guessing a model. Other errors are not retried or substituted. The request body limit is 28,000 UTF-8 bytes. A sole eligible option skips Jev.

## Configuration

`enabled` defaults to `false`. Enabling requires at least one `candidates` entry with `model` and `description` (optionally `provider`); model ids are not fixed in code. `effortDescriptions` maps model ids or more specific `provider/model` routes to descriptions keyed by adapter effort id. Only supported levels are offered; missing descriptions use the adapter's own description or name. Copy [`examples/jev-policy.patch.yml`](examples/jev-policy.patch.yml) into a private profile overlay and set `enabled: true` and a Harness credential reference. Profile patches replace the entire config: overriding only `enabled` discards the policy. Changes to descriptions affect future evaluations, not existing session pins.

`logDecisions` defaults to `false`. Enable it in a test profile to log Session id, question, attempt, HTTP status, duration, selected key, and 503 fallback source through the Harness logger. It never logs conversation text, the request body, or credentials, and does not write routing diagnostics to the Session log. Set absolute `diagnosticLogFile` to append the same sanitized events as JSONL (new files are mode `0600`). The file is not automatically rotated; clean it up after diagnosis. Write errors warn without failing generation. `credentialRefs` defaults to an empty list; configure at least one reference when more than one choice is available. `stateDirectory` defaults to `~/.dsh-jev-router/sessions` and must be absolute. `maxBodyBytes` and `timeoutMs` may be lowered but cannot exceed the version-one bounds. Records belong to the selected Session id and must be retained with Session logs across deployments. Do not share one state directory between unrelated installations that reuse Session ids.

## Model Experience

Jev makes two separate small evaluate calls on a Session's first automatic request and one effort call per later main request. A sole option needs no evaluate call. These calls use the user's gateway quota, not the selected model's provider tokens. Actual generation uses the selected adapter and its normal token accounting and KV cache; switching the concrete model starts a new provider cache context. A later effort change keeps the request-level effort, and on Responses adds a `configuration_update`, so the prefix before that item can still hit. Selector values never reach the adapter.

## Known Limitations and Deferred Work

This version does not monitor for better models, auto-load skills, split oversized evaluations, retry errors other than HTTP 503, impose an effort floor, or show routing cost. Per-Session sidecars require shared durable storage when sessions move to another host. Session selection and provider-call headers are durable in Harness; task-description updates affect future evaluations only.
